# ব্যবহার-পরিসংখ্যান প্ল্যান

কাজটা হারুনের। সিদ্ধান্ত হয়েছে ২০২৬-১১-২৩। এখনো কোনো কোড লেখা হয়নি।

## কী জানতে চাই

1. মোট কতবার ডাউনলোড হয়েছে, প্ল্যাটফর্ম অনুযায়ী।
2. এখন কতগুলো কম্পিউটারে কীবোর্ডটা ইন্সটল করা আছে এবং চলছে।
3. বিজয় আর ফোনেটিক: কোনটা কতজন ব্যবহার করে।
4. ক্র্যাশ রিপোর্ট।
5. ভার্সন অনুযায়ী ইন্সটলের সংখ্যা।
6. রিটেনশন: ইন্সটলের ১, ৭ আর ৩০ দিন পরেও কীবোর্ড চালু আছে কিনা।
7. দেশ। সার্ভার IP দেখে দেশ বের করবে, কিন্তু IP কোথাও সংরক্ষণ করবে না।

আনইন্সটলের কারণ জিজ্ঞেস করা আপাতত বাদ।

## যা কখনো পাঠানো যাবে না

কীবোর্ড ব্যবহারকারীর সব লেখা দেখে, পাসওয়ার্ডও। তাই কোনো পিং বা ক্র্যাশ রিপোর্টে নিচের কিছুই থাকবে না:

- টাইপ করা কোনো লেখা, শব্দ, অক্ষর বা কী-এর ক্রম। শুধু সংখ্যা পাঠানো যাবে।
- কোন অ্যাপে টাইপ হচ্ছে।
- IP ঠিকানা, কম্পিউটারের নাম, ইউজারনেম, ফাইলের পাথ।

কোড রিভিউয়ের সময় প্রথমেই এই তালিকা মিলিয়ে দেখতে হবে।

## কাজের তালিকা

### ক. ডাউনলোড গোনা (১)

অ্যাপের কোড ছুঁতে হবে না।

- [ ] `scripts/download-stats.sh` লেখো। এটা `gh api repos/Nukta-Solutions/nukta-bangla-keyboard/releases --paginate` দিয়ে
      প্রতিটি রিলিজের প্রতিটি ফাইলের `download_count` যোগ করবে। ফলাফল দেখাবে প্ল্যাটফর্ম অনুযায়ী (`NuktaBangla.dmg`,
      `NuktaBangla-Setup.exe`, `nukta-bangla-linux.sh`) আর রিলিজ অনুযায়ী।
- [ ] Homebrew cask-ও GitHub-এর একই ফাইল নামায়, তাই সেটা এই সংখ্যার মধ্যেই আছে। আলাদা করে গোনার দরকার নেই।

### খ. সার্ভার (২, ৩, ৫, ৬, ৭)

- [ ] একটা ছোট এন্ডপয়েন্ট বানাও। সুপারিশ: Cloudflare Worker আর D1। এতে প্রায় কোনো খরচ নেই, সব ডেটা নিজেদের হাতে
      থাকে, আর `request.cf.country` থেকে দেশ সরাসরি পাওয়া যায়, IP ছুঁতেই হয় না। অন্য কিছু ব্যবহার করতে চাইলে আগে আসিফের সাথে কথা বলো।
- [ ] `POST /ping` নিচের JSON নেবে। সার্ভার এর সাথে আজকের তারিখ আর দেশের কোড যোগ করে একটা সারি রাখবে।
      IP বা পুরো হেডার কোথাও লগ হবে না (Worker-এর লগিংও দেখে নাও)।

```json
{
  "id": "6f1c…",          // ইন্সটলের সময় তৈরি র‍্যান্ডম UUID v4, কারো পরিচয়ের সাথে সম্পর্ক নেই
  "platform": "windows",   // windows | macos | linux
  "version": "1.0.6",
  "os": "10.0.26100",      // OS ভার্সন; Linux-এ ডিস্ট্রোর নাম আর ভার্সন
  "arch": "x86_64",        // x86_64 | arm64
  "layout": "phonetic",    // এই মুহূর্তে বাছাই করা লেআউট: bijoy | phonetic
  "bijoyKeys": 1520,       // গত পিং-এর পর বিজয়ে কতবার কী চাপা হয়েছে (শুধু সংখ্যা)
  "phoneticKeys": 0        // একইভাবে ফোনেটিকে
}
```

- [ ] একটা সাদামাটা ড্যাশবোর্ড পেজ বা SQL কোয়েরি, যা থেকে এগুলো পাওয়া যাবে:
  - **সক্রিয় ইন্সটল (২):** গত ৩০ দিনে কতগুলো আলাদা `id` থেকে পিং এসেছে, প্ল্যাটফর্ম অনুযায়ী।
  - **বিজয় আর ফোনেটিক (৩):** সক্রিয় ইন্সটলগুলোর মধ্যে কোন লেআউট ব্যবহার হয়েছে (যার `bijoyKeys` বা `phoneticKeys` > 0),
    আর মোট কী চাপার কত ভাগ কোন লেআউটে।
  - **ভার্সন (৫):** প্রতিটি সক্রিয় `id`-এর সর্বশেষ `version` ধরে গোনা।
  - **রিটেনশন (৬):** প্রতিটি `id`-এর প্রথম পিং-এর তারিখ থেকে হিসাব হবে, ১, ৭ আর ৩০ দিন পরে পিং এসেছে কিনা।
    আলাদা "ইন্সটল" ইভেন্টের দরকার নেই।
  - **দেশ (৭):** সক্রিয় ইন্সটল দেশ অনুযায়ী।

### গ. অ্যাপে পিং (তিন প্ল্যাটফর্ম)

আপডেট চেক এখনই দিনে একবার চলে। পিং ঠিক সেখানে বসাও, যাতে নতুন কোনো টাইমার না লাগে:

| প্ল্যাটফর্ম | আপডেট চেক যেখানে | লেআউট সেটিং যেখানে |
|---|---|---|
| Windows | `windows/src/bin/bar.rs` (`update::State::check_due`), `windows/src/update.rs` | `windows/src/settings.rs` (`Layout`) |
| macOS | `Sources/NuktaInputMethod/Updates.swift` (`checkIfDue`) | `Sources/NuktaInputMethod/Settings.swift` |
| Linux | `linux/nukta_bangla/updates.py` (`check_if_due`) | `linux/nukta_bangla/settings.py` |

- [ ] প্রথমবার চালু হলে একটা UUID তৈরি করে আপডেট-স্টেট যে ফোল্ডারে রাখা হয় সেখানে সংরক্ষণ করো, তারপর সবসময় সেটাই ব্যবহার করো।
- [ ] কী চাপার সংখ্যা গোনো শুধু একটা কাউন্টারে, লেআউট অনুযায়ী। কোন কী চাপা হয়েছে তা কোথাও রাখা যাবে না।
      পিং সফল হলে কাউন্টার শূন্য করে দাও।
- [ ] পিং ব্যর্থ হলে চুপচাপ বাদ দাও, ব্যবহারকারীকে কিছু দেখাবে না। পরের দিন আবার চেষ্টা হবে।
- [ ] সেটিংসে একটা অপশন রাখো "ব্যবহারের পরিসংখ্যান পাঠান"। এটা বন্ধ করলে পিং আর ক্র্যাশ রিপোর্ট দুটোই বন্ধ হবে। Linux-এ
      যেমন `autoUpdateCheck` আছে, তেমন একটা কী যোগ করো। ডিফল্টে চালু থাকবে নাকি বন্ধ, **সেটা আসিফ ঠিক করবে।**
- [ ] কী পাঠানো হয়, তা বাংলায় এক-দুই লাইনে লেখো সেটিংস বা About-এ, আর ওয়েবসাইটের প্রাইভেসি পাতায়। কোনো লেখায় Avro বা অভ্রর নাম থাকবে না।
- [ ] টেস্ট লেখো: পিং-এর JSON-এ ওপরের ফিল্ডগুলো ছাড়া আর কিছু নেই, আর অপশন বন্ধ থাকলে কোনো পিং যায় না।
      Linux-এ `linux/tests/test_updates.py`-এর মতো করে, Windows-এ `cargo test`, macOS-এ `Tests/`-এ।

### ঘ. ক্র্যাশ রিপোর্ট (৪)

- [ ] সুপারিশ: Sentry। Windows-এ Rust-এর `sentry` crate, macOS-এ `sentry-cocoa`, Linux-এ `sentry-sdk`।
      পিং-এর মতো এটাও সেটিংসের অপশন মেনে চলবে।
- [ ] এই সেটিংসগুলো বাধ্যতামূলক, কারণ ক্র্যাশের সময় মেমরিতে ব্যবহারকারীর লেখা থাকে:
  - breadcrumbs বন্ধ রাখো।
  - শুধু স্ট্যাক ট্রেস পাঠাও। ফুল মেমরি ডাম্প, attachments বা local variables পাঠানো যাবে না।
  - `send_default_pii` বন্ধ রাখো, IP সংরক্ষণও বন্ধ রাখো।
  - `before_send`-এ ক্র্যাশের বার্তা থেকে বাংলা বা যেকোনো ইনপুট লেখা মুছে দাও। যেমন Python-এর `KeyError('ক')` বার্তায় অক্ষরটা নিজেই থাকে।
- [ ] Windows: টেক্সট সার্ভিসটা DLL, যা অন্যদের অ্যাপের ভেতরে চলে। তাই সেখানে প্রসেস-জুড়ে ক্র্যাশ হ্যান্ডলার বসানো যাবে না।
      শুধু আমাদের কোডের panic ধরো। `bar.exe` আর `settings.exe` আমাদের নিজেদের প্রসেস, সেখানে পুরো হ্যান্ডলার বসানো যাবে।
- [ ] macOS: dSYM আপলোড করার একটা ধাপ `scripts/release-mac.sh`-এ যোগ করো, যাতে রিলিজের সময় নতুন কোনো কাজ না বাড়ে।
